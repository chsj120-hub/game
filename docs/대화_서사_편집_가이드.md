# 대화·서사 편집 가이드

## 1. 어디에 무엇이 있나
| 파일 | 누가 씀 | 내용 |
|---|---|---|
| `tools/gen_story.py` | 생성기 | 초안 생성 규칙(노드 유형별 NPC·장면 문구, 선택지 3종, 동선 자동 생성, 미니게임 변형) |
| `tools/story_legends.py` | 사람 | 국보급 유산 전설 사전(핵심어 → 인물·전설·단서), 동료 분류별 말투 |
| `data_src/story/drafts/*.json` | 생성기 | 초안. 매번 새로 쓰이므로 **고치지 않습니다** |
| `data_src/story/edits/*.json` | **사람** | 수정본. 초안 위에 깊은 병합되고 절대 덮어쓰이지 않습니다 |
| `data/24_story.json` | 생성기 | 게임이 읽는 최종본(초안 + 수정본) |
| `docs/대화_서사.xlsx` | 생성기 | 대사·선택지 한 줄씩(엑셀 편집용) |

초안(생성 규칙)과 수정본(사람 손)이 서로 다른 파일에 있습니다. 그래서 동료나 동선이 바뀌어 초안을 다시 만들어도, 고친 대사는 그 위에 다시 얹힙니다. 수정본에는 **바꿀 부분만** 적습니다.

## 2. 작업 순서
```
python3 tools/story_tool.py list --kind recruit           # recruit·promotion·gear·recipe·lore, --status draft|edited|final
python3 tools/story_tool.py show q_cp_chakho              # 대본처럼 보기
python3 tools/story_tool.py edit q_cp_chakho              # edits/recruit.json 에 편집용 사본 생성 → 직접 고침
python3 tools/story_tool.py check                         # 병합 + 전체 검증(validate_data)
```
엑셀로 고칠 때: `story_tool.py export` → `docs/대화_서사.xlsx` 수정(`text`·`who`·`req`·`effects`·`result` 칸) → `story_tool.py import docs/대화_서사.xlsx`. 바뀐 칸만 `edits/xlsx_import.json`에 들어갑니다.

다 고친 서사는 `"status": "final"`로 표시해 두면 `list --status draft`에서 빠집니다.

## 3. 서사 형식
키는 `quest:<퀘스트 id>`입니다. 영입은 `q_<동료 id>`, 승급은 `promo_<동료>_<등급>`, 장비·탈것은 `q_<아이템 id>`, 비전 전수는 `q_rcp_*`, 전설은 `q_lore_*`입니다.
```json
{"status": "draft", "title": "동료 영입: 착호갑사",
 "intro": 장면,              // 수락할 때
 "steps": [장면, 장면, ...], // 동선 i번째 노드에 도착할 때 (개수 = 동선 노드 수, 검증기가 확인)
 "outro": 장면}              // 완료할 때
```
장면:
```json
{"bg": "ND_16_CITY_GYEONGSEONGDOHOBU",
 "cast": ["hero", "cp_chakho", "npc:official:아전 강씨"],
 "lines": [{"who": "cp_chakho", "text": "…"}],
 "choices": [{"id": "know", "text": "〔불(佛) 2〕 …", "req": {"knowledge": {"bul": 2}}, "effects": {"knowledge_xp": {"bul": 25}}, "result": "착호갑사: …"}]}
```
- `bg`: 노드 id·유산 id·`res://` 경로 중 하나. 그림은 `assets/scenes/nodes/<노드 id>.png` → 공식 노드 삽화 → `assets/scenes/<노드 유형>.png` 순서로 찾고, 셋 다 없으면 유형별 색을 깝니다.
- `who`: `hero`(주인공) · 동료 id · `npc:<역할>:<표시 이름>`. 역할은 official·monk·elder·soldier·merchant·shaman·scholar·fisher·innkeeper·traveler이고, 상반신은 `assets/portraits/npc_<역할>.png`입니다. 그림이 없으면 실루엣과 이름을 그립니다.
- `cast`: 화면에 설 인물(최대 3명, 주인공은 늘 왼쪽). 비우면 대사의 화자로 채웁니다.
- `result`: 고른 뒤 나오는 한 줄입니다. `이름: 대사` 형식이면 그 이름표로 나옵니다.

### 선택지 조건(req)과 효과(effects)
조건을 채우지 못한 선택지도 가운데 목록에 나오지만, 비활성으로 두고 뒤에 `✕ 사유`를 붙입니다.

| req 키 | 예 | 사유 표시 |
|---|---|---|
| `rank` | `3` | 신분 Rank 3 필요 |
| `money` | `120` | 엽전 120냥 필요(보유 …) |
| `items` | `{"mat_charcoal": 6}` | 참숯 ×6 필요 |
| `knowledge` | `{"sang": 3}` (파티 합산) | 상(상업) 지식 3 필요(파티 …) |
| `party` | `"cp_c05"` 또는 목록 | 심마니 동행 필요 |
| `class` | `"cls_merchant"` | 상인 전용 |
| `flag` | `"paid:cp_chakho"`, `"!met_x"` | 조건 미충족 / 이미 선택한 길 |
| `visited` | 노드 id | ○○ 방문 필요 |

| effects 키 | 의미 |
|---|---|
| `knowledge_xp` | 지식 경험치 `{"gong": 60}` |
| `money` | 엽전 ±(음수 = 지출) |
| `give` / `take` | 물품 주기 / 가져가기 `{"id": 수량}` |
| `flag` | 플래그 켜기(`"x"`)·끄기(`"!x"`), 나중에 `req.flag`로 분기 |
| `reputation` | 명성(자동 보상 공식 밖이라 되도록 쓰지 않음) |
| `money_mult` | 이벤트 전용: 완료 보상 엽전 배율 |

초안은 퀘스트마다 선택지 하나를 둡니다. 지식 조건(파티 지식이 등급+1 이상), 엽전(등급별 지출), 조건 없음, 이렇게 세 갈래이고 비전 전수에는 재료 지참이 하나 더 붙습니다. 어느 쪽을 골라도 퀘스트는 진행되고 보상 공식도 그대로이며, 달라지는 것은 지식 경험치와 지출뿐입니다. 고른 값은 `flags["choice:<장면 키>"]`에 남습니다.

### 이벤트 단계(20 시트)
단계에 `"dialogue": 장면`을 넣으면 그 장면을 씁니다. 없으면 `text`를 그 노드 유형의 NPC가 말하는 한 장면으로 만듭니다. `choice` 단계의 선택지에도 `req`를 붙일 수 있습니다.

## 4. 새 퀘스트 규칙
- **비전 전수(`recipe`)**: 유산이 주는 특산물 비전서를 기증·매각해 잃었을 때 여는 두 번째 길입니다. 그 권역에 있을 때만 목록에 나오고, 이미 가진 비전서면 숨깁니다. 동선은 `route_rules`를 따르고 마지막 노드는 그 특산물의 산지입니다. 보상은 비전서이고 명성 0.3배·엽전 0이며 `economy_sim`이 보정에 반영합니다.
- **전설(`lore`)**: 국보·국보급·세계기록유산, 그리고 원래 있던 5등급 유산 83곳이 대상입니다. 튜토리얼·시나리오가 가리키는 유산은 제외합니다. 같은 권역에서 4등급은 3노드, 5등급은 4노드를 거치고 마지막 노드가 그 유산입니다(`00_overview.lore_quest_rules`). 완수해야 답사할 수 있고 보상은 0입니다. 다음 목표가 은닉 노드면 단서로 지도에 드러납니다.
- 전설 문구는 `tools/story_legends.py`의 `LEGENDS`에서 유산 이름의 핵심어로 찾습니다. 역사 기록과 설화를 참고한 **가상 각색**이고, 1861년 뒤에 발굴된 사실은 "소문·전설"로만 다룹니다. 사전에 없는 유산은 분류별 일반 단서를 씁니다.
- 동선·조건을 바꾸려면 `edits/*.json`의 `"quests": {"q_lore_001": {"route": [...]}}`에 적습니다. 그때 `steps` 개수도 같이 맞춰야 합니다.

## 5. 미니게임 변형 자동화
같은 미니게임 구현을 쓰되 유산마다 **내용 데이터만** 바꿉니다(`24_story.mg_variants.<유산 id> = {minigame, params}`). 런타임은 `MinigameBase.create_from_catalog(id, overrides)`로 카탈로그 기본값 위에 덮어씁니다.

| 분류 → 미니게임 | 유산마다 달라지는 것 (등급이 오를수록 어려움) |
|---|---|
| 도자 → 파편 맞추기, 회화 → 한지 슬라이딩 | 판 크기 3·4·5, 그림 `assets/minigames/heritage/<유산 id>.png`(없으면 기본 그림) |
| 비·석탑·마애 → 탁본 | 판목 무늬 시드, 필요 인출률 76~92%, 먹방망이 크기 |
| 불상·범종 → 타종, 금속 → 단조 | 명중대 폭·속도·명중 수, 명중대 위치 시드 |
| 민속 → 부적 획순 | 점 5~9개 배치(시드), 판정 반경 |
| 전적·건축 → 유산 문답, 무덤 → 제향 진설 | 권역·답사지·분류·지정 구분·사상 계열·설명 고르기·전설 인물 문항을 데이터에서 자동 출제 + 분류별 기본 문항, 필요 정답 2~4 |
| 침몰선 → 인양 | 장력 허용 폭·흔들림·유지 비율 |

어떤 유산에 미니게임이 붙는지는 `mg_policy`가 정합니다. 은닉 유산, 기본 미니게임이 있는 노드 유형, 3등급 이상 공개 유산, 전설 대상이 여기에 들고, 명승과 1~2등급 도시·사찰은 바로 답사합니다. 특정 유산만 바꾸려면 `edits/*.json`에 `"mg_variants": {"her_n085": {"params": {"need": 2}}}`처럼 적고, 유산 데이터에 `minigame`이 있으면 그 값을 먼저 씁니다.

## 6. 테스트 요령 (제주 김만덕 편)
- 제주목의 「제주 삼도동 탐라성주 옥인」(4등급 국보)은 [거점]에서 `전설 퀘스트 필요`로 보입니다. 누르면 전설 따라가기를 바로 수락할 수 있습니다(Rank 3 필요).
- 제주 관덕정 같은 3등급 공개 유산을 답사하면 그 유산 전용 문답이 나옵니다.
- 영입(예: 보부상)·승급 퀘스트를 수락하면 수락 장면 → 노드마다 장면 → 마지막 노드의 가운데 선택지 → 완료 장면 순서로 나옵니다. 지식·엽전이 모자란 선택지는 회색으로 나오고 사유가 붙습니다.
- 대화 중 `건너뛰기 ▶▶`를 누르면 선택지나 끝으로 바로 넘어갑니다. 숫자키 1~9로 선택지를 고를 수 있습니다.
