# 수정 가이드 — 무엇을 고치려면 어디를 여나

직접 테스트한 뒤 값·문구·콘텐츠를 고칠 때 보는 안내서입니다. 어떤 수정이든 순서는 같습니다.

```
① 찾기      python3 tools/overrides.py where <id 또는 이름 일부>
② 고치기    아래 표에서 정한 "고칠 곳" 한 군데만
③ 반영      python3 tools/run_pipeline.py --fast    (전투·밸런스 수치를 바꿨으면 --fast 없이)
④ 확인      끝에 "OK"가 나오면 게임(Godot)에서 실행 → 출력 패널 확인
⑤ 저장      git add -A && git commit -m "무엇을 왜 고쳤는지"
```

## 0. 가장 중요한 규칙: `data/*.json`을 직접 고치지 않는다
`data/`는 게임이 읽는 **결과물**입니다. 여러 생성기가 파이프라인을 돌 때마다 이 파일을 통째로, 또는 일부 행만 다시 씁니다. 직접 고친 값이 다음 실행에서 사라질 수 있다는 뜻입니다(실제로 시험해 보니 `01_heritage`·`regions`·`08`·`16`·`23`·`24`는 전부, 나머지도 생성기가 만든 행은 다시 써졌습니다).

그래서 사람 손이 닿는 곳을 셋으로 나눴습니다. 생성기는 이 셋을 **읽기만** 합니다.

| 사람이 고치는 곳 | 무엇 | 도구 |
|---|---|---|
| `data_src/overrides/*.json` | 모든 시트의 값(숫자·문구·목록), 규칙 수치(00_overview), 새 행 추가 | `tools/overrides.py` |
| `data_src/story/edits/*.json` | 대사·선택지·전설·비전 전수 퀘스트·유산별 미니게임 변형 | `tools/story_tool.py` |
| `data_src/scenarios/*.json` | 시나리오(메인 스토리·튜토리얼·전용 이벤트) | `tools/scenario_tool.py` |

월드 자체(노드 배치·권역·유산 목록)를 바꾸는 큰 수정만 원천 파일(§4)을 엽니다.

## 1. 자주 하는 수정 바로 찾기
| 하고 싶은 일 | 방법 |
|---|---|
| 적 체력·공격력 | `overrides.py set en_dokkaebi hp 180` → 전체 파이프라인(전투 시뮬 확인) |
| 장비 수치·가격 | `set eq_w1_mokgeom stats.atk 5` · `set eq_w1_mokgeom acquire.price 80` |
| 아이템·유산·노드 이름이나 설명 | `set her_001 name "경주 불국사"` · `set <노드 id> note "…"` |
| 특산물 시세 | `set sp_jeonju_hanji base_price 24` |
| 스킬 위력·AP | `set sk_chakho_shot power 1.4` · `ap_cost 2` |
| 동료 능력치·영입 조건 문구 | `set cp_c05 hp 90` · `set cp_c05 recruit.condition "…"` |
| 퀘스트 종류별 보상 배율 | `set overview economy.quest_type_mult.recipe.rep 0.4` |
| 이동 속도·피로·허기 | `set overview movement.v_base 85` · `survival.fatigue_per_tick …` |
| 동선 규칙(퀘스트 노드 수·권역) | `set overview route_rules.3.nodes [3,3]` (전설은 `lore_quest_rules`) |
| 신분(Rank) 기준 | 직접 못 고침 — 자동 보정값입니다. §3 참고 |
| 새 적·아이템 추가 | `overrides.py copy en_dokkaebi en_my_goblin --name "산도깨비"` → `local.json`의 `add`에서 값 수정 |
| 대사·선택지·선택 조건 | `story_tool.py edit <퀘스트 id>` 또는 엑셀 왕복 → [대화_서사_편집_가이드.md](대화_서사_편집_가이드.md) |
| 유산 미니게임 난이도·문항 | `data_src/story/edits/*.json` 의 `mg_variants` (같은 가이드 §5) |
| 미니게임 기본값(모든 유산 공통) | `set mg_bell params.zone 0.18` (21 시트 행) |
| 노드 유형별 기본 미니게임 | `set doc:21_minigames.json node_type_default.ruin mg_takbon` |
| 시나리오·튜토리얼 | [시나리오_작성_가이드.md](시나리오_작성_가이드.md) |
| 그림·초상·배경 넣기 | §5 |
| 게임 동작(코드) | §6 |

`set`의 값은 JSON으로 읽습니다. 숫자는 `7`, 목록은 `[3,3]`, 참·거짓은 `true`로 쓰고, 그 밖은 문자열로 봅니다. 공백이 들어간 문장은 따옴표로 감쌉니다.

## 2. overrides 자세히
```
python3 tools/overrides.py where 도깨비              # 후보 목록(id·시트)
python3 tools/overrides.py where en_dokkaebi         # 한 행의 모든 필드 + 고칠 곳 안내 + "← 덮어쓰기 중" 표시
python3 tools/overrides.py set en_dokkaebi hp 180    # data_src/overrides/local.json 에 기록하고 바로 data/ 에 적용
python3 tools/overrides.py unset en_dokkaebi hp      # 기록을 지우고 원래 값 150 으로 되돌림
python3 tools/overrides.py list                      # 걸려 있는 수정 전부
```
직접 파일을 써도 됩니다. 주제별로 나누면 여러 사람이 동시에 고쳐도 충돌하지 않습니다(예: `balance_적.json`, `문구_유산.json`). 파일 이름 순서로 합치고, 같은 칸을 두 파일이 고치면 뒤 파일이 이깁니다.
```json
{
 "rows":     {"en_dokkaebi": {"hp": 180, "res": {"holy": -0.2}}},
 "overview": {"economy": {"quest_type_mult": {"recipe": {"rep": 0.4}}}},
 "docs":     {"21_minigames.json": {"node_type_default": {"ruin": "mg_takbon"}}},
 "add":      {"12_enemies.json:enemies": [{"id": "en_my_goblin", "name": "산도깨비", "...": "기존 행을 copy 해서 고치기"}]}
}
```
- **병합 규칙:** `{}`는 깊게 합치고, 목록·숫자·문자열은 통째로 바꿉니다. 목록 하나만 고치려 해도 전체를 다시 적어야 합니다(`skills`, `drops`, `route` 등).
- **되돌리기:** 기록을 지우면(`unset` 또는 파일에서 삭제) 다음 적용 때 원래 값으로 돌아갑니다. 그 사이 생성기가 새 값을 만들었다면 그 새 값을 둡니다.
- **적용 시점:** 파이프라인에서 동료 병합 다음, 서사 생성(`gen_story`)·경제 보정(`economy_sim`) 앞입니다. 그래서 유산 이름을 바꾸면 전설 대사에도, 퀘스트 개수를 바꾸면 신분 보정에도 반영됩니다.
- **막아 둔 것:** `rank.table`·`rank.formula`·`provinces`처럼 자동으로 계산되는 칸은 오류로 막습니다(§3). 24 시트는 `story/edits`로 안내합니다.
- **새 행:** 반드시 `copy`로 기존 행을 복제해 시작하세요. 필드가 모자라면 검증기가 `KeyError`로 멈출 수 있습니다. 새 적이 나오는 곳은 그 행의 `spawn_conditions`(`regions`·`nodes`)로 정합니다. 이벤트에 쓰려면 단계의 `waves`에 넣습니다.

## 3. 밸런스 수치 — 무엇이 자동이고 무엇을 고치나
공식과 계수는 전부 `data/00_overview.json` 한 곳에 있고, 게임(`scripts/autoload/Balance.gd`)과 시뮬레이터(`tools/common.py`)가 같은 공식을 씁니다.

| 칸 | 뜻 | 고쳐도 되나 |
|---|---|---|
| `economy.heritage_rep/money`, `quest_rep/money` | 유산·퀘스트 보상 곡선(base·growth) | 됨. Rank 기준이 자동으로 다시 맞춰짐 |
| `economy.quest_type_mult` | 퀘스트 종류별 배율(gear·mount·companion·recipe·lore …) | 됨 |
| `economy.category_mult`, `hidden_mult`, `rank_gap`, `venue` | 유산 분류·은닉·신분 격차·기증처 배율 | 됨 |
| `route_rules`, `lore_quest_rules` | 동선 큐 노드 수·권역 범위 | 됨. 기존 동선이 규칙을 어기면 검증기가 알려 줌 |
| `movement`, `survival`, `time`, `weather_table` | 이동·생존·시간 | 됨. `travel_sim`으로 확인 |
| `battle`, `capture`, `barracks` | 전투·포획·막사 | 됨. 전체 파이프라인(전투 시뮬) 필수 |
| `trade`, `town_dev`, `crafting` | 무역·도시 발전·제작 | 됨. `trade_sim` 확인 |
| `content_plan` | 계획 수량(`economy_sim --plan` 비교용) | 됨 |
| `rank.table`·`formula`·`reputation_budget`, `provinces[].standing_req` | 신분 임계·도 명성 요건 | **안 됨(자동)** |

신분 기준은 `economy_sim`이 "균형형 플레이어가 콘텐츠 1/3을 찾으면 Rank 5"가 되도록 매번 다시 계산합니다. Rank를 빠르게 또는 느리게 하고 싶으면 보상 곡선(`quest_rep` 등)이나 시뮬레이터의 목표 비율을 바꿔야 합니다. 엽전 여유 비율은 실행 결과의 "엽전 여유" 표에서 확인하세요(현재 1.47 / 1.93 / 2.85).

## 4. 월드·유산·동료 원천 (큰 수정)
| 바꾸려는 것 | 원천 파일 | 다시 만드는 단계 |
|---|---|---|
| 노드 추가·삭제·유형, 권역 인접, 뱃길 | `data_src/world_table.json` (`regions[].city/town/…`, `hidden`, `sea_routes`, `overrides`) | `build_world` |
| 노드 좌표 | `data_src/node_geo.json` → 지형까지 `run_pipeline.py --terrain` | `build_world`·`gen_terrain` |
| 수작업 유산(보상 지정)·등급 | `data_src/heritage_curated.json` (`curated`, `tier_overrides`) | `build_world` |
| 국가유산 448 원본 | `data_src/heritage450/heritage_450.xlsx` | `import_heritage450` |
| 동료 65명 원본 | `data_src/db15/DB15_원본.xlsx` | `db15/audit_fix` → `merge_companions` |
| 역사·설화 이벤트, 권역 적, 무예 장비 | `tools/content_expand.py` 안의 목록 | `content_expand` |

- 노드 id(`ND_…`)는 이름에서 만들어지므로 **이름을 바꾸면 id도 바뀝니다**. 표시 이름만 바꿀 때는 `overrides.py set <노드 id> name "…"`이 안전합니다.
- 아이템 id가 바뀌면 옛 세이브의 배낭에 옛 id가 남습니다. `scripts/autoload/GameState.gd`의 `ID_MIGRATION`에 `"옛 id": "새 id"`를 넣으면 불러올 때 바꿔 줍니다(없는 id는 정리하고 알림). 저장 구조를 바꾸면 `SAVE_VERSION`을 올리세요.

## 5. 그림·소리 넣기 (코드 수정 없음)
- 경로와 규격은 `assets/ASSET_MANIFEST.json`(`path`·`spec`)에 있고, 프롬프트는 `assets/prompts/*.csv`에 있습니다. 파일을 그 경로에 같은 이름으로 넣기만 하면 되고, 없으면 게임이 대체 그림을 그립니다.
- 대화 배경: `assets/scenes/<노드 유형>.png`(공용), `assets/scenes/nodes/<노드 id>.png`(그 노드 전용, 우선)
- 대화 인물: `assets/portraits/<동료 id>.png`, `npc_<역할>.png`, `hero_<직업 id>.png`
- 유산 퍼즐 그림: `assets/minigames/heritage/<유산 id>.png`
- 새 에셋 종류를 추가했다면 `tools/gen_asset_manifest.py`에 항목을 넣어 목록에 남깁니다.

## 7. 실패했을 때
| 증상 | 원인·해결 |
|---|---|
| `✗ <단계> 에서 멈춤` | 그 아래 마지막 20줄이 원인입니다. 고친 뒤 `run_pipeline.py --from <단계>`로 이어서 실행 |
| `validate_data` `[오류] … 참조 누락 'x'` | 없는 id를 가리킴. `where`로 정확한 id 확인 |
| `동선 N노드 (허용 …)`, `동일 권역 규칙 위반` | 동선이 `route_rules`에 안 맞음 → 동선이나 규칙 수정 |
| `steps N개 ≠ 동선 M노드` | 서사를 고치며 동선 길이가 달라짐 → `steps` 개수 맞추기 |
| `[overrides] id 'x' 없음` | 원천에서 그 행이 사라졌거나 id 오타 → 기록 수정·삭제 |
| `KeyError: '…'` | 새 행에 필수 필드가 빠짐 → `copy`로 만든 행과 비교 |
| `balance_sim`/`db15/balance_check` FAIL | 적·스킬 수치가 목표 승률 밖 → 수치를 조금씩 되돌림 |
| 게임에서 고친 값이 안 보임 | 파이프라인을 안 돌렸거나, 옛 세이브를 불러옴 → 새 게임으로 확인 |
| 무엇을 바꿨는지 모르겠음 | `git status`, `git diff data_src`. 되돌리기는 `git checkout -- <파일>` |

## 8. 작업 습관
- 한 번에 한 주제만 고치고 바로 파이프라인을 돌려, 무엇 때문에 결과가 바뀌었는지 알 수 있게 합니다.
- 사람이 고친 내용은 `data_src/overrides`·`data_src/story/edits`·`data_src/scenarios`에 모입니다. 검토할 때는 `git diff data_src`만 봐도 됩니다(`data/` 변경은 그 결과).
- 커밋 메시지에 "무엇을·왜"를 적어 두면 나중에 되돌릴 때 편합니다(예: `도깨비 체력 150→180: 2등급 초반 너무 쉬움`).
